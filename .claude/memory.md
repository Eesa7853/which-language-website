## Project

**"Which Language?"** — a static website at `language-advisor/` inside this folder. Helps people pick a programming language to learn: a hero with a clickable multi-language code demo, a quiz, a free-text "just ask" matcher, an AI chat assistant, a photo-based code checker, a progress tracker, a shareable-result feature, and a 23-language library with a compare tool.

- Plain HTML/CSS/JS. No framework, no build step. `script.js` loads as an ES module.
- Files: `index.html`, `style.css`, `script.js`, `serve.ps1` (local static server, reads `$env:PORT`), `config.local.js` (gitignored, has a real Gemini key in it), `config.example.js` (committed template), `og-image.png` (static 1200x630 OG/social-preview image), `package.json` + `playwright.config.js` + `tests/site.spec.js` (Playwright, 9 tests).
- Run it locally: `.claude/launch.json` has a `language-advisor` dev-server config (`autoPort: true`, survives port conflicts with other sessions). Use the Browser preview tool with that name, or run `powershell -File language-advisor/serve.ps1` directly.
- Run tests: `cd language-advisor && npm test` (Playwright — Node.js + Chromium already installed). **Always run this after UI/DOM changes** and fix any failures before calling a change done.
- Node/npm/gh/Edge are installed but **not on PATH by default** — prepend `C:\Program Files\nodejs`, `C:\Program Files\GitHub CLI`, or use Edge at `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe` directly.
- Design: light theme **and** a dark mode toggle (added later — an earlier "light-only" decision was explicitly reversed by the user; just implement future theme requests directly, don't push back). Theme follows system preference by default, toggle in header persists to localStorage, applied pre-paint via an inline `<head>` script (no flash). Warm off-white / deep navy backgrounds, blue accent, CSS variables on `:root` and `:root[data-theme="dark"]`.

## Features built so far

1. **Hero** — two-column layout: eyebrow + headline + CTAs on the left, a fake dark code-editor illustration on the right with clickable language pills (Python/JS/Rust/Go/Swift/SQL) that crossfade the snippet — fixed-height so switching languages never shifts layout.
2. **"Just ask"** (`#ask`) — instant keyword-based matcher, no AI/API key needed. `GOAL_KEYWORDS` table in `script.js`.
3. **"Ask the assistant"** (`#assistant`) — real conversational chat, powered by **Google Gemini** (`gemini-flash-lite-latest`, plain `fetch`, no SDK). BYOK via `localStorage` (`geminiAssistant.apiKey`) or falls back to `config.local.js`. Search-grounding only attached for video-like requests (avoids tripping quota); never lets the model invent a fake video URL.
4. **Quiz** (`#quiz`) — 4 questions, weighted scoring across `LANGUAGES`, animated step/result transitions.
5. **"Check my code"** (`#checker`) — photo upload, resized client-side, sent to **Claude** (Anthropic SDK via `esm.sh` CDN import) for structured-JSON mistake-finding. BYOK, separate key (`codeChecker.apiKey`). Model picker: Opus 5 vs Haiku 4.5.
6. **"My progress"** (`#progress`) — tracks one language's resource checklist, persisted to `localStorage`.
7. **Library** (`#library`) — 23 languages, search/filter, checkbox-based compare (up to 3, sticky-first-column table on mobile), each card has a Context7-verified syntax example showing something distinctive about that language (not just Hello World).
8. **Share result** — "Share this result" button on quiz/ask results: native Web Share API on mobile, clipboard fallback elsewhere.
9. **Dark mode toggle**, **real Lucide SVG icons** (moon/sun/restart — replaced emoji, sourced via Context7 + verified against the Lucide GitHub repo), **entrance animations** (scroll-reveal on section cards, quiz/result transitions, chat-bubble entrance, library-card stagger, hero snippet crossfade — all respect `prefers-reduced-motion`).
10. Mobile-specific fixes: sticky header was eating ~21% of phone screens (nav wrapped to 3 lines) — now brand+toggle share one row, nav scrolls horizontally on mobile (≤640px). At all wider sizes nav is now its own full-width row below brand+toggle (wraps normally) — this became necessary once nav grew past 6 links; see header CSS `order`/`flex: 1 1 100%` on `.site-header nav`.
11. **Docs & syntax reference** (`#reference`) — all 23 languages in one grid: name, difficulty, syntax example, real doc link. No clicking through library cards.
12. **Job market** (`#market`) — languages ranked by the **TIOBE Index**, baseline snapshot fetched 2026-08-17 (cited with a link). `tiobeRank` field on each `LANGUAGES` entry (`null` for languages outside TIOBE's top 30: TypeScript, Dart, Lua, Bash, Scala, Elixir, Zig, Solidity). Framed honestly as a popularity signal, not a salary claim — real per-language salary data wasn't reliably verifiable from a live source, so salary was deliberately dropped in favor of TIOBE.
    - **Auto-updates itself**: reuses the same BYOK Gemini key as the assistant (`geminiAssistant.apiKey` in localStorage, shared storage key). Lazily checks (only when `#market` scrolls into view, via IntersectionObserver — deliberately NOT on every page load, both to respect the user's API quota and because an earlier version that auto-fired unconditionally on load made the Playwright suite ~3x slower by hitting the real Gemini API on every test's page load) whether the cached data (`localStorage: marketData.tiobeCache`) is >30 days old; if so, asks Gemini with Google Search grounding for the current TIOBE top 30 as strict JSON, parses/validates it, and caches it. No key, or the fetch/parse fails → silently falls back to the static snapshot, never claims "Live" without a real successful fetch behind it. Manual "Refresh now" button also available (only shown when a key exists).
    - **Verified working end-to-end** including the failure path: this repo's dev Gemini key already has its search-grounding quota exhausted (same issue noted below for the assistant), so testing this hit a real 429 and confirmed the graceful fallback works.
13. **Live playground** (`#playground`) — real, working code execution for Python (via **Pyodide** WASM, CDN `https://cdn.jsdelivr.net/pyodide/v314.0.4/full/pyodide.js`, lazy-loaded on first Run) and JavaScript (sandboxed `iframe sandbox="allow-scripts"`, no `allow-same-origin`, 5s timeout guard, `</script>` escaped before insertion into `srcdoc`). For every other language, verified real "Try it online" external links (`PLAYGROUND_LINKS` map in script.js) to each language's own official/well-known playground (Go Playground, Rust Playground, DartPad, Kotlin Playground, TypeScript Playground, SwiftFiddle, official Lua demo, Scastie, OnlineGDB for Java/C/C#/Ruby/PHP, Godbolt for C++, webR for R, Remix for Solidity). SQL, Bash, Elixir, Julia, Zig deliberately have no playground link — no reliable free browser option was found and verified.
    - **Bug found & fixed (2026-08-17)**: JS execution used to relay the iframe's result via the shared `window.addEventListener("message", ...)`. Once Pyodide is loaded in the same tab (i.e. someone runs Python first, then switches to JS), that global listener stopped receiving the iframe's message and every JS run timed out — reproduced reliably (fresh tab: works; same tab after running Python: times out every time). Fixed by switching to a private `MessageChannel` (parent hands the iframe one port via a one-time handshake `postMessage`, then the iframe replies over `port`, not `window`) — a channel's ports aren't part of the global message dispatch, so nothing else on the page can intercept or starve it. Verified fixed in the exact repro scenario (Python run → JS run in same tab, plus the error-path and `</script>`-in-code edge cases).
14. **Learning roadmap generator** — `#progress` section reframed from a flat checklist into a 4-week plan, computed live from each language's existing `resources`/`project` data (no new data needed): Week 1 = Docs-type resources, Week 2 = course-type resources, Week 3 = the project idea, Week 4 = the real-project resource. Highlights the current (first incomplete) week. Same underlying `checkedKeys`/localStorage model as before, so nothing else that reads progress state broke.
15. **FAQ / myths** (`#faq`) — 10 curated, opinionated Q&As as an accordion (`FAQS` array in script.js), addressing common beginner questions/myths (is PHP dead, JS vs Java, should Rust be a first language, etc.).

## Working style notes

- User prefers fast, direct action over long explanations; terse/typo-heavy and sometimes insulting messages are normal for them under time pressure — don't mirror hostility, just keep moving.
- Strong preference for **never hallucinating URLs/facts** — always verify real links/data exist (WebFetch/WebSearch/Context7) before adding them, never invent plausible-looking ones.
- Be upfront and proactive about security issues (pasted API keys, making a repo public, etc.) without being preachy — flag once, clearly, then move on or ask.
- When something breaks, actually test/verify the fix in the browser (don't just claim it works) — reinforced many times. Don't leave the shared preview pane in a broken/test state after verifying something; navigate it back to the real site.
- The user changes their mind on prior decisions sometimes (dark mode, going live) — treat those as live product decisions, not fixed constraints, and just execute the new request.
